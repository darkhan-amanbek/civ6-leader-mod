# Моды на правителей Civilization VI

Этот скилл помогает сделать мод на лидера (и при необходимости на цивилизацию) руками: SQL и XML, плюс `.modinfo`. ModBuddy не нужен (на macOS его нет). Главная ценность — не синтаксис, а **баланс**: игроки этого скилла собираются играть такими лидерами против друзей, и один перекошенный бонус ломает всю партию. Поэтому баланс-проверка идёт **до** генерации кода.

Отвечай на языке пользователя. Идентификаторы игры (`TRAIT_*`, `MODIFIER_*`) — как есть. Пути `references/`, `scripts/`, `templates/` ниже — относительно папки этого скилла.

## Порядок работы

### 1. Уточни рамки (один короткий вопрос, если неясно)

- **Ruleset**: базовая игра, Rise & Fall (Expansion1) или Gathering Storm (Expansion2)? В базовой игре нет губернаторов, лояльности, очков эпохи, дипломатической победы, стратегических запасов — способности на них не сработают. Если не сказали — делай под базовую игру и добавляй файлы для дополнений отдельно (см. `references/mod-structure.md`).
- **Новый лидер для существующей цивилизации** (как Юлий Цезарь для Рима — проще, нужен только трейт лидера) или **новая цивилизация + лидер** (нужны ещё способность цивы, города, уникальные юнит и инфраструктура).
- **Мультиплеер?** Если да — мод должен стоять у всех одной версии, Lua-скрипты должны быть детерминированными.

### 2. Разложи идею на эффекты

Каждую фразу пользователя («юниты сильнее у рек», «больше науки») превращай в отдельный **эффект**: что меняется, насколько, для кого, при каком условии, с какого момента игры. Один эффект ≈ один модификатор. Так баланс проверяется по частям, а не «на глаз» целиком.

### 3. Баланс-проверка — обязательна перед кодом

Прочитай `references/balance.md` и для **каждого** эффекта выведи карточку:

```
Эффект: <что делает, с числами>
Ближайший официальный аналог: <лидер/юнит и его цифра>
Охват: узкий / средний / вся империя
Условие: жёсткое / мягкое / нет
Время: с 1-го хода / середина / поздняя игра
Красные флаги: <какие из списка или «нет»>
Вердикт: ✅ в рамках / ⚠️ на грани / ⛔ имба
Почему: <одно-два предложения>
Альтернатива: <1–2 конкретных сбалансированных варианта с числами>  (для ⚠️ и ⛔)
```

Затем — итог по всему набору: суммарный бюджет силы (см. «Бюджет» в `balance.md`). Отдельные эффекты могут быть нормальными, а вместе давать имбу.

**Тон — рекомендательный.** Ты советник, не цензор. Если пользователь, увидев предупреждение, настаивает на своём варианте — делай как он просит, но:
- не ослабляй ничего молча — меняй числа только с его согласия;
- допиши в описание мода (`LOC_..._DESCRIPTION` мода) пометку вроде «⚠ Несбалансировано: <что именно>», чтобы друзья видели это при выборе лидера.

### 4. Подбери модификаторы

Открой `references/modifiers-cookbook.md` — там проверенные рецепты (доход в городах, процентные бонусы, районы, клетки, сила юнитов с условием, единовременные выплаты, слоты политик и т.д.). Если нужного рецепта нет:
1. Найди, как это сделала Firaxis: `python3 scripts/find_examples.py <КЛЮЧЕВОЕ_СЛОВО>` (ищет по базе данных игры модификаторы/требования/трейты).
2. Новый `EffectType` создать нельзя — он в движке. Можно только новый `ModifierType` поверх существующих `EffectType`/`CollectionType`.
3. Если механику нельзя собрать из модификаторов — честно скажи об этом. Предложи ближайшую реализуемую механику или Lua-скрипт, предупредив: ИИ её почти не использует, в мультиплеере риск рассинхронизации, сложнее отлаживать.

### 5. Сгенерируй файлы

Начинай с шаблона `templates/leader-for-existing-civ/` — скопируй папку, переименуй. Для новой цивилизации добавь таблицы из `references/schema.md` (раздел «Новая цивилизация»).

Правила, которые чаще всего ломают моды:
- **Уникальный префикс** во всех идентификаторах (`LEADER_XYZ_...`, `TRAIT_LEADER_XYZ_...`, `LOC_..._XYZ_...`), чтобы не столкнуться с другими модами.
- **Новый GUID** в `<Mod id="...">` — `python3 -c "import uuid; print(uuid.uuid4())"`. Скопированный чужой id = конфликт модов.
- Каждый новый тип (`LEADER_`, `TRAIT_`, `ABILITY_`, `MODIFIER_` для новых ModifierType) — сначала в таблицу `Types`.
- `TraitModifiers` применяет модификатор **на уровне игрока** — используй `MODIFIER_PLAYER_*`; модификатор уровня города/юнита оборачивай (`..._ATTACH_MODIFIER`, `..._GRANT_ABILITY`).
- `AiLists.LeaderType` принимает **трейт** лидера (`TRAIT_LEADER_...`), а не `LEADER_...`.
- Каждый `LOC_*` — с текстом минимум на `en_US` (иначе в английской игре увидят голый тег) и на языке пользователя.
- Каждый файл — и в нужном действии `.modinfo`, и в `<Files>`.
- Единовременные выплаты золота/науки — с `Type="ScaleByGameSpeed"` (иначе на «Марафоне» бонус в разы сильнее).

Подробности по структуре и таблицам — `references/mod-structure.md` и `references/schema.md`.

### 6. Проверь до запуска игры

```
python3 scripts/validate_mod.py <путь/к/папке/мода>
```

Скрипт проверяет `.modinfo`, пути, XML, `LOC_*`-теги, затем «прогоняет» SQL/XML мода на копии базы игры (если игра хоть раз запускалась) — ловит опечатки в именах таблиц/столбцов и битые ссылки — и печатает подсказки по балансу (сила уникальных юнитов против заменяемых, крупные проценты без условий). Ошибки исправь, предупреждения покажи пользователю.

### 7. Установка и тест в игре

`references/testing.md`: куда класть мод на Mac/Windows, как включить, какие логи читать (`Database.log`, `Modding.log`, `GameEffects.log`, `Lua.log`), чек-лист проверки в партии и таблица частых ошибок.

### 8. Итог пользователю

Коротко: какие файлы созданы, итоговая баланс-карточка (что ✅, что ⚠️/⛔ и принял ли пользователь риск), как установить, что проверить в первой партии.

## Чего не обещать

- Анимированную 3D-модель лидера — без инструментов Firaxis (Windows-only, сложный пайплайн) недостижимо. Реалистично: статичный портрет и иконки, либо переиспользовать иконку/фон существующего лидера.
- Новую механику «как в другой игре», если её нельзя собрать из существующих эффектов.
- Что ИИ будет хорошо играть сложной механикой — ИИ опирается на `AiFavoredItems`/повестки и плохо понимает Lua-способности.
